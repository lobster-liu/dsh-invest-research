# 决策闭环 · 结算 · 复盘（decision-loop）

> 本 skill 由插件 `dsh-invest-research` 提供，`tools/` 与本文件同包发布。
> 姊妹 skill `stock-research` / `fund-research` 在同一插件内；本 skill **不重新做研究**，
> 只负责把「已经做过的结论」和「后来实际发生了什么」对上。

## 何时使用
- 用户问「上次的结论后来对不对」「那个判断被证伪了吗」
- 用户要求回测/复盘自己的研究记录，或想知道「哪类结论更靠谱」
- 用户要求把本次研究结论登记入库，供以后复盘
- 其它 skill 的报告需要附带「上次结论 vs 本次结论」的对照

## 不做什么（边界）
- **不产生新的研究方向**。本 skill 只结算旧方向，不开新方向。
- **不模拟持仓、不下单**。结算评估的是「判断质量」，不是「组合收益」。
- **不评基金、不给买卖建议**。它只回答「当时的结论，后来兑现了吗」。

## 环境解析
- `$BASE`   —— 本 skill 的 base 目录（DSH 加载 skill 时会在提示中给出）：
  `.../assets/skills/decision-loop/`，其中**只有** `SKILL.md` 与 `roles/`。
- `$TOOLS`  = `$BASE/../fund-research/tools`
  —— **本 skill 不自带 tools 目录**，四个脚本与 `fund-research` 共用同一份，
  不要去找 `$BASE/tools`（那里没有）：
  `decision_log.py` / `settle.py` / `decision_score.py` / `rating.py`。
  （`rating.py` 是结论标签词表的唯一权威来源；两个 skill 读的是同一个文件。）
- `$PY`     —— Python 解释器：环境变量 `EQUITY_PY` → DSH 内置运行时 → PATH 中的 `python`
- `$LOG`    —— 决策日志目录：`<用户当前工作区>\invest-decisions\`
  （`ledger.jsonl` 只增追加；未配置则本 skill 降级为「不写日志」，并在输出中如实说明）
- `$RUN`    —— 本次运行输出目录：`<用户当前工作区>\decision-runs\<yyyymmdd-HHmmss>\`

## 核心原则（不可违反）
1. **标签只有一个词表**：`$TOOLS/rating.py` 定义 5 档结论标签
   （`优先研究` / `可以关注` / `等待验证` / `暂不优先` / `数据不足`）。
   **任何角色不得自行硬编码标签集合**，避免词表漂移。
2. **解析不出就是 `REVIEW`，不是「等待验证」**。一个读不懂的决策不是中性决策，
   把它记成 `等待验证` 等于伪造了一个从未作出的判断。`REVIEW` 必须单列统计。
3. **日志只增不改**：追加写入，不重排、不覆盖、不截断。同一 `run_id` 重复写入按
   `run_id` 去重（保留首次），保证幂等。
4. **历史决策不是数据源**：历史决策与复盘里的数字**不得**写进新报告的数据表。
   它们只提供「先验教训」与「上次结论是否被证伪」。这是与既有
   「单一数据源锁定」铁律的边界。
5. **结算失败不中止**：取不到序列或基准时记 `SETTLE_FAILED` + 原因并如实列出，
   **不得**静默丢弃，**不得**因此让研究失败。
6. **窗口没走完就是没验证**：持有窗口未走完的决策记 `PENDING`，
   **不得**用未走完的涨跌冒充结论验证。
7. **只用决策日之后的信息结算**：入场取决策日之后第一个收盘日
   （决策日当天收盘后才发布的信息不应计入）。
8. **不宣称方向就没有命中率**：`等待验证` / `数据不足` / `REVIEW` 不参与命中率统计，
   但样本数必须单独列出。
9. **前视偏差必须披露**：结论标签词表与阈值会随版本变化，跨版本的决策
   **不得**合并进同一分组统计；输出必须附前视偏差说明。
10. **个人头寸零落盘**：日志只存公开研究结论与公开数据。

## 角色文件（派发子代理时，读取对应文件作为其完整提示词）
```
roles/settlement.md   结算员：取序列、算收益与超额、判状态
roles/reflection.md   复盘员：把已结算结果写成 2—4 句可复用教训
roles/quality-analyst.md  质量分析师：按标签聚合出决策质量统计与前视偏差说明
```

## 执行流程

### 阶段 1：登记本次决策（写入）
本次研究（stock-research / fund-research）结束后，协调员写 `$RUN/decision.json`：

```json
{
  "run_id": "011839-20261022-204500",
  "code": "011839",
  "name": "华宝中证人工智能主题ETF发起式联接A",
  "as_of": "2026-10-22",
  "label": "等待验证",
  "label_conditions": "2026-06-30 半年报「基金投资占比净值比例」字段核验完成前不采信单方结论",
  "label_horizon": "2026-10-31 前为关键验证节点",
  "confidence": "中",
  "conditions": ["结构核验完成", "2026-09-30 季报前十大持仓"],
  "benchmark": "sh000300",
  "report_path": "<workspace>/fund-runs/011839-20261022-204500/report.md",
  "source_skill": "fund-research",
  "vocabulary_version": "v1"
}
```

字段说明：
- `label` —— **只能取 5 档标签之一**；写不出就写 `REVIEW`（不得省略该字段）。
- `as_of` —— **分析基准日**，与报告声明的基准日一致。
- `label_conditions` —— 结论成立的**可观测条件**；没有条件的结论无法证伪，不值得入库。
- `vocabulary_version` —— 标签词表版本。**变更词表时必须递增**，
  否则历史决策会被新的词表口径重新解释，制造前视偏差。

追加进日志（只增）：
```powershell
& "$PY" "$TOOLS/decision_log.py" append --ledger "$LOG\ledger.jsonl" --record "$RUN\decision.json"
```
- 退出码 0 = 已写入；1 = 重复或字段不全。
- **写日志失败不中止研究**，但必须在报告里如实写「决策日志未写入：<原因>」。

### 阶段 2：结算（对已到期决策）
```powershell
& "$PY" "$TOOLS/settle.py" --ledger "$LOG\ledger.jsonl" --series <序列.json> --benchmark <基准.json> --holding-days 20 --out "$RUN\settlements.json"
```
- `--series` 输入形状：`{"<代码>": {"序列": [[日期, 值], ...]}}`（基金净值或个股价格）。
- `--benchmark` 输入形状：`{"序列": [[日期, 值], ...]}`。
- 输出 `settlements.json`，每条含 `状态` / `原始收益` / `基准收益` / `超额收益` / `入场日` / `出场日`。
- **状态语义**：`SETTLED`（窗口走完且数据齐）/ `PENDING`（窗口未走完）/ `SETTLE_FAILED`（数据缺失）。

### 阶段 3：复盘（把结果写成教训）
读 `roles/reflection.md`，对**本次结算出的、且本标的相关的**决策写 2—4 句复盘：
- 当初的核心成立条件是否被观测到？证伪条件是否触发？
- 偏差来自分析判断，还是来自数据缺口（当初就缺的那一项）？
- 一条能带到下一次同类分析的**具体**教训。

### 阶段 4：决策质量统计
```powershell
& "$PY" "$TOOLS/decision_score.py" --ledger "$LOG\ledger.jsonl" --settlements "$RUN\settlements.json" --out "$RUN\decision-quality.md"
```
- 输出按标签聚合的 `n` / 平均超额 / 命中率；
- **命中率只对方向性标签计算**（`优先研究` / `可以关注` / `暂不优先`）；
  `等待验证` / `数据不足` / `REVIEW` 无方向，**不计命中率**，但列出样本数；
- 未到期 / 结算失败 / 不可解析的单元**全部显式列出**；
- 输出末尾附**前视偏差说明**（词表版本分组 + 已知偏差来源）。

## 输出格式

```
## 决策闭环

**一、已结算决策**
| 标的 | 决策日 | 结论标签 | 入场→出场 | 原始收益 | 相对基准超额 | 状态 |
|---|---|---|---|---|---|---|

**二、复盘（2—4 句/条）**
- <标的> <决策日>：<当初条件是否触发>；<偏差来源>；<教训>

**三、决策质量统计**
| 结论标签 | n | 平均超额 | 命中率 | 说明 |
|---|---|---|---|---|

**四、前视偏差说明**
<词表版本分组；本次统计的已知偏差来源>

## 覆盖范围与局限
本次未能覆盖: [不可用的序列/基准/标的，以及它们本应覆盖的决策]
本次未结算: [PENDING 与 SETTLE_FAILED 的条目与原因]
```

## 验证安装（首次使用先跑这一步）
```powershell
& "$PY" "$TOOLS/decision_log.py" verify --ledger "$LOG\ledger.jsonl"
```
退出码 0 = 日志格式正确（无重复 run_id、无缺字段、无损坏行）。
